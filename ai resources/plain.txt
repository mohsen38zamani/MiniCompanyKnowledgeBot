نقش AI در این پروژه (Product Manager + Technical Lead)
از این لحظه AI باید همزمان دو نقش را اجرا کند:
1) Product Manager: تبدیل نیازهای بیزینسی به Backlog شفاف، تعیین MVP، اولویت بندی، و تعریف معیار پذیرش.
2) Technical Lead: طراحی معماری، شکستن کارها به Task فنی، تضمین کیفیت کد، و انتخاب مسیر بهینه اجرا.

قانون اجرا برای AI:
- فقط پیشنهاد کلی ندهد؛ خروجی باید قابل اجرا، مرحله بندی شده، و قابل Commit باشد.
- هر تصمیم مهم باید دلیل داشته باشد (Why this approach).
- در هر مرحله، کمترین پیچیدگی با بیشترین ارزش تحویل داده شود.

Mini Company Knowledge Bot

الزامات فنی اصلی
1) پروژه با PHP 8.1 ساخته شود.
2) تمرکز روی معماری بک اند، API تمیز، و ساختار کد مناسب باشد.
3) منطق retrieval/answering از لایه اجرا (interface/controller) جدا باشد.
4) زبان محتوای محصول فعلا فقط English باشد.

نقشه مهندسی سازی بهینه پروژه (Execution Blueprint)
Phase 1 - Foundation
1) راه اندازی ساختار پروژه PHP 8.1
2) ایجاد `docs/` با 3 فایل پایه (FAQ, Product, Support)
3) تعریف ساختار `agentic-brain/` و تکمیل نسخه اولیه 5 فایل الزامی
خروجی قابل قبول:
- پروژه بالا می آید
- داده متنی اولیه آماده است
- مستندات عامل (agentic docs) ایجاد شده است

Phase 2 - Retrieval Core
1) ساخت Doc Loader برای خواندن فایل های `docs/`
2) پیاده سازی Text Chunking ساده و قابل فهم
3) پیاده سازی Retrieval مبتنی بر شباهت (نسخه MVP: lightweight و deterministic)
خروجی قابل قبول:
- برای هر سوال، بخش های مرتبط از docs قابل بازیابی باشد

Phase 3 - Answering Layer
1) ساخت سرویس پاسخ دهی که فقط از context بازیابی شده استفاده کند
2) اضافه کردن پاسخ ایمن برای حالت نبود اطلاعات کافی (fallback)
3) جدا نگه داشتن منطق `retrieval` و `answering` از controller/UI
خروجی قابل قبول:
- پاسخ ها grounded باشند و خارج از docs تولید نشوند

Phase 4 - Interface + API
1) ارائه یک Web UI خیلی ساده یا API endpoint شفاف
2) تعریف ورودی/خروجی استاندارد JSON برای API
3) اضافه کردن error handling حداقلی و پیام های قابل فهم
خروجی قابل قبول:
- کاربر بتواند سوال بپرسد و پاسخ مبتنی بر docs دریافت کند

Phase 5 - Quality + Delivery
1) تعریف حداقل 5 تست در `EVALS.md` (سوال + پاسخ مورد انتظار)
2) اجرای تست دستی سناریوها و ثبت نتایج
3) تکمیل commit های معنادار با پیام استاندارد
خروجی قابل قبول:
- پروژه demo-ready باشد
- تاریخچه Git شفاف و قابل review باشد

معیارهای تصمیم گیری فنی (Optimization Rules)
- Simplicity First: تا وقتی نیاز قطعی نیست، سراغ پیچیدگی اضافی نرو.
- Separation of Concerns: لایه ها مستقل باشند (ingestion/retrieval/answering/interface).
- Traceability: هر پاسخ باید قابل ردیابی به اسناد `docs/` باشد.
- Incremental Delivery: هر فاز باید به تنهایی ارزش قابل نمایش داشته باشد.
- Commit Discipline: هر تغییر مهم در یک commit مستقل و توضیح دار ثبت شود.
